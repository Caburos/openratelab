A Klaviyo abandoned cart flow that is not triggering is almost never one big mystery. It is one item on a short list, and the fastest way to find it is to check that list in order, from the cheapest check to the most involved, before anyone rebuilds the flow.

The order that saves the most time is flow status first, then whether the trigger event is actually reaching Klaviyo, then the filters, then the individual profile's status. Each step rules out a whole category of causes, so by the third check most people have found it.

## Check Whether The Flow And Its Emails Are Actually Live

A flow can look finished and still send nothing. Open the flow and look at the status in the top corner. A flow in draft or manual status does not run on its own, and individual emails inside the flow have their own status as well. An email left in draft or manual means the flow reaches that step and then does nothing with it.

This is the most common cause on a freshly built or recently edited flow, because someone saved changes, duplicated an email, or switched a status while testing and never switched it back. It takes ten seconds to check and it is the least dignified explanation, which is why it gets skipped.

## Confirm The Trigger Event Is Reaching Klaviyo

A live flow can only start when its trigger event arrives, so the next question is whether the event is being recorded at all. Open a recent profile who you know started a checkout and read their activity feed. Look for the checkout-started or added-to-cart event, whichever metric your flow is built on.

If the event is missing for that profile, the break is between your store and Klaviyo. Check that the store integration is still connected and syncing, and that nothing changed recently on the storefront, such as a theme update, a checkout customization, or an app that alters the checkout. If the event is present, the integration is fine and the cause is further down.

One thing that surprises people here: the event only attaches to a profile once the shopper is identified. A visitor who adds to cart and leaves before typing an email address produces no profile to send to. Those carts are lost to the flow by design, not by failure.

## Look For Filters Quietly Excluding People

If the event arrives and the flow is live, read the filters. A flow has trigger filters, which decide whether a given event starts the flow, and flow filters, which decide whether a profile is allowed to receive messages at all. Either one can exclude far more people than intended.

Common examples are a trigger filter on cart value set higher than most carts, a filter that excludes anyone who has already purchased once, or a flow filter that references a segment which no longer contains what you expect. Read each condition literally, as if you were the system, and ask whether your test profile would pass it.

This is also where a flow that used to work stops. A filter that referenced a property or segment that later changed will keep excluding people long after the person who built it has forgotten it exists.

## Check The Profile, Not Just The Flow

When status, event, and filters all look right, the remaining cause lives on the individual profile. Email flows only send to profiles who can receive marketing email, so someone who is unsubscribed, never consented, or suppressed after a bounce or spam complaint is skipped without any warning on the flow itself.

Two more profile-level behaviors catch people out. A profile that is still inside an earlier run of the same flow will not simply start a second run on top of it, so repeat testing with the same address can look like the flow has stopped working. And smart sending, if enabled on the emails, skips a message when the profile received something recently, which can look like a flow failure when it is a safeguard working as designed.

For your own testing, use a fresh, subscribed address that has never been through the flow. Testing with an address that has already been through it is the most common reason a working flow looks broken.

## Prove The Fix Without Waiting A Week

Do not wait for customers to tell you the flow works. Start a checkout with a clean test profile, enter the email at the first step, leave without ordering, and watch what happens in Klaviyo. The activity feed shows whether the event arrived. The flow's analytics show whether the profile was queued or skipped, and the reason for a skip points straight at the filter or the profile status responsible.

Once the test passes, compare trigger events against flow entries over the next few days. A gap between the two is the number worth tracking, because it shows how many shoppers the flow is actually reaching, and it is the same logic we use when a flow is [underperforming for other reasons](/blog/traffic-not-converting-email-flows).
